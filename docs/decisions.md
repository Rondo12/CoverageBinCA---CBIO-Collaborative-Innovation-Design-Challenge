# Decisions log

A short record of each choice and the reason for it, so we can explain it to judges and to each other.
Newest at the bottom.

| Date | Decision | Why |
|---|---|---|
| 2026-09-28 | We report projected **coverage**, never measured diversion. | We have no bin-weight or audit data. Coverage (the share of estimated waste-generating foot traffic that has a bin within reach) is what the model can actually claim. |
| 2026-09-28 | Every estimated number is labeled `PLACEHOLDER`. | So judges and Facilities can tell measured values from assumptions. |
| 2026-09-28 | Python 3.12 locally. | Google Colab runs 3.12, so "works on my laptop" means "works in Colab". |
| 2026-09-28 | The model places one **co-located station** (trash + recycling + compost) per site. | Keeps a first model simple and matches how current bins will be counted (1 station = 1 unit). |
| 2026-09-28 | Campus data ships a precomputed `distances.csv` (demand point to candidate site, meters). | Ronnie's model only has to choose sites; no geometry code in the model notebook. |
| 2026-09-28 | Distances are straight-line, not walking routes. | Simple and reproducible. Walking distance is longer, so real coverage may be lower; we state this limitation. |
| 2026-09-28 | OpenStreetMap data is saved as snapshots in `data/osm/`. | Notebooks never depend on the Overpass API being up, and results are reproducible. |
| 2026-09-28 | Anything from Facilities goes in `data/private/` (gitignored). | The repo is public. We share Facilities data only once they say it's OK. |
| 2026-09-28 | `outputs/chosen_sites.csv` and `outputs/map.html` are tracked in git; the rest of `outputs/` is ignored. | The map reads the model's output, so it has to reach GitHub, and we want to share the map. |
| 2026-09-28 | One owner per file. | Avoids merge conflicts for a first-time GitHub team. Ronnie owns `notebooks/02_model.ipynb`; Eric owns the data, maps and `01_campus_data.ipynb`. |

| 2026-10-06 | Demand built from OpenStreetMap proxies: building weight = footprint m² × floors (1 if unknown) × use factor; parking = area × 0.05; food/drink spots get an extra fixed weight (restaurant 2000, cafe 1500, vending 300). All PLACEHOLDER, in `binopt/config.py`. | Facilities hasn't sent data. Proxies let the whole pipeline run now; real numbers become a config or file swap. |
| 2026-10-06 | Building use type: OSM tags first, then name keywords, then "academic" for any other named building, "unknown" (factor 0.5) for unnamed ones. | Most OSM buildings here are tagged only `building=yes`; the names carry the information. |
| 2026-10-06 | Shade canopies (`building=roof`) and covered bridges are not demand. Buildings mapped only as a dot get a 500 m² footprint (PLACEHOLDER). | Canopies are mostly parking shade, not places people spend time. Dots have no outline to measure. |
| 2026-10-06 | Distance to a building or parking lot is measured to its nearest **edge**, not its center (`DISTANCE_FROM = "edge"`). | People leave buildings through doors on the edge. With center distances no outdoor bin could cover the library or the stadium at 50 m. |
| 2026-10-06 | Candidate sites: a pin every 25 m along walkways (not stairs, road crossings or traffic islands), plus the walkway spot nearest each building (`near_building`); nothing within 3 m of any building; pins under 10 m apart merged. All PLACEHOLDER. | OSM maps only 1 entrance on campus, so "nearest walkway to the building" stands in for "near the entrance". |
| 2026-10-06 | Every site starts as `accessible = unknown`. | OSM doesn't reliably record wheelchair routes, curb cuts or surfaces on campus. Facilities must confirm. |
| 2026-10-06 | About 3% of demand weight (mostly unnamed back-lot and farm-unit buildings) has no candidate within 50 m. | OSM has no walkways mapped near them. We report this as a data gap; we don't invent paths. |
| 2026-10-06 | Current-bins loader accepts CSV, XLSX or GeoJSON with any common column names; 1 row = 1 co-located station unless a `units`/`stations` column says otherwise.
